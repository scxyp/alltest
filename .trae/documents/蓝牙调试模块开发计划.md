# 蓝牙调试模块开发计划

## Context

项目已有串口、网络、Modbus 三个调试模块，均通过 `DebugFeature` 接口注册到 `FeatureRegistry`。用户要求开发蓝牙调试模块，经确认采用 **BLE（低功耗蓝牙）** 方案，使用 **universal_ble** 包（BSD-3 开源，跨平台含 Windows，API 简洁活跃维护）。

模块需融入现有分层架构（data/domain/presentation），复用 `ReceivePanel`、`SendPanel`、`DebugLogEntry`、`QuickCommand` 等共享组件，实现设备扫描、连接、GATT 服务/特征浏览、特征读写与 Notify 订阅、HEX/文本收发、循环发送、快捷指令、持久化。

## 依赖

- `universal_ble: ^2.3.0` — BLE 扫描/连接/GATT 读写/Notify
- Windows 需声明 `bluetooth` + `radios` capability（`windows/runner/DebugProfile_UWP` 不需要，此为 Win32 应用）

## 文件清单

### data 层
- `lib/features/bluetooth/data/ble_service.dart` — 对 universal_ble 的封装，提供扫描启停、连接/断开、服务发现、读写、Notify 订阅/取消的简化 API，统一异常处理
- `lib/features/bluetooth/data/ble_store.dart` — SharedPreferences 持久化快捷指令、发送历史、上次连接设备 ID（仿 `serial_store.dart`）

### domain 层
- `lib/features/bluetooth/domain/ble_device_info.dart` — 扫描结果模型（deviceId、name、rssi、广告数据）
- `lib/features/bluetooth/domain/ble_session.dart` — 单个 BLE 连接会话，`extends ChangeNotifier implements SendPanelController`；管理连接状态、GATT 服务/特征树、Notify 订阅、收发日志与统计、循环发送；接收数据走 `DebugLogEntry.receive`，发送走 `DebugLogEntry.transmit`
- `lib/features/bluetooth/domain/ble_session_manager.dart` — `extends ChangeNotifier implements QuickCommandStore`；管理多会话（最多 4 个）、扫描状态、快捷指令与发送历史；仿 `SerialSessionManager`

### presentation 层
- `lib/features/bluetooth/presentation/bluetooth_feature.dart` — `DebugFeature` 实现，id='bluetooth'，蓝色 0xFF4A90D9，Icons.bluetooth
- `lib/features/bluetooth/presentation/bluetooth_page.dart` — 主页面：AppBar 扫描按钮 + 新建连接按钮；空态引导；非空时 `TiledLayout` 平铺会话视图（仿 `serial_page.dart`）
- `lib/features/bluetooth/presentation/widgets/scan_dialog.dart` — 扫描对话框：实时列表展示扫描到的设备（名称/RSSI/地址），可选过滤名称，点击选中返回设备 ID
- `lib/features/bluetooth/presentation/widgets/session_view.dart` — 单会话视图：顶部状态栏（设备名 + 连接/断开按钮 + 循环发送徽章），中部 GATT 服务/特征树（可折叠展开），选中可写特征后底部显示 `SendPanel`，右侧/下方 `ReceivePanel` 展示收发日志（仿 `serial/session_view.dart`）
- `lib/features/bluetooth/presentation/widgets/service_characteristic_tree.dart` — GATT 服务/特征树形展示，每个特征标注权限（读/写/Notify），点击可读特征触发单次读，点击可 Notify 特征切换订阅

### 注册
- `lib/core/bootstrap.dart` — 添加 `..register(BluetoothFeature())`

### 测试
- `test/bluetooth_test.dart` — BLE 设备模型 toJson/fromJson 往返；BleSession 状态机逻辑（断开时 sendContent 抛异常）；Store 持久化 round-trip

### Windows 配置
- `windows/runner/RunnerCapability` — 确认 `bluetooth` capability（若 universal_ble 需要）

## 关键设计

### 扫描流程
1. 用户点击"新建连接" → 弹出 `ScanDialog`
2. 调用 `UniversalBle.startScan()` → 监听 `UniversalBle.scanResults` 流
3. 实时更新设备列表，显示名称/RSSI/地址
4. 用户选中设备 → 停止扫描 → 创建 `BleSession` 并 `connect`

### 会话生命周期
- `BleSession.connect()`：调用 `UniversalBle.connect(deviceId)`，成功后 `discoverServices()` 获取 GATT 树
- 连接断开：监听 `UniversalBle.connectionStateChange` 流，断开时标记会话、停止循环发送、flush 接收缓冲
- 可选特征：连接后默认展示服务/特征树，用户选择一个可写特征作为发送目标

### 数据收发
- 发送：通过 `UniversalBle.write(deviceId, serviceId, characteristicId, data)` 写入选定的可写特征
- 接收：通过 `UniversalBle.subscribeToCharacteristic` 订阅 Notify/Indicate 特征，收到数据走 `DebugLogEntry.receive`，与串口模块一致使用静默判帧（30ms 合并）
- 循环发送：复用 `SendPanelController.startLoopSend/stopLoopSend`

### GATT 树交互
- 服务/特征以可折叠 `ExpansionTile` 列表展示
- 每个特征标注权限图标（读眼镜/写笔/Notify 铃铛）
- 读特征：点击 → 单次 `read` → 结果写入日志面板
- Notify 特征：点击 → 切换订阅/取消订阅 → 订阅期间数据流入日志面板
